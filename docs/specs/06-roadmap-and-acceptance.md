# 06 施設内部まで作るための開発タスク

## 到達目標

一般的な世界・町・施設・船・建物を対象に、**施設の内部（複数フロア・部屋・廊下・壁・扉・階段・大型設備・家具）まで一つの汎用アプリで作図**できる。階層は数値管理で、5段階に固定しない。既存マップの位置と色は勝手に変更しない。

## 優先順位と検証

| 優先 | タスク | 現状 | 完了条件 |
|---|---|---|---|
| P0 | 旧 `level` → 数値 `displayLevel` への移行設計 | 仕様のみ | 任意深度、既存データ互換、親子循環なし |
| P0 | 任意深度の階層ツリー・選択・親子展開 | large/mediumを固定的に扱う | 全体→地区→施設→部屋→設備を任意に行き来 |
| P0 | 親区画と子地区の重ね塗り解消 | 親子の表示構造が未移行 | 形状維持、表示・境界線のみ正しく分離 |
| P0 | 既存中層の親子移行 | 全体と4地区が同じlarge | コアシェル・リファイン→4地区→施設→内部区画の関係を保持 |
| P1 | 図形の直接作図・頂点・サイズ編集 | 数値中心 | マウス/タッチで部屋・多角形を描いて調整 |
| P1 | グリッド/点/辺へのスナップ | グリッド表示のみ | 任意ON/OFF、自由配置も可 |
| P1 | 壁・間仕切り作図と実厚 | 図形roleとして追加可能 | 外枠と別に手で描画・厚み保存 |
| P1 | 扉の壁上配置・開口・接続 | 扉図形のみ | 扉幅で壁が開き、部屋間接続を保存 |
| P1 | 親施設に子部屋追加・追従移動 | 親ID指定は可能 | 親移動時、内部配置を保って子も移動 |
| P1 | 物理フロアの追加・切替・複製 | 未実装 | 地下・地上の複数階と階段接続を保存・表示できる |
| P1 | 家具・大型設備の配置 | 共通図形のみ | フロアと部屋に所属する設置物を移動・回転・複製・保存できる |
| P2 | 編集ロック・複数選択・整列・回転 | 未実装 | ロックを尊重し、安全に複数編集 |
| P2 | 接続経路と通行検証 | 未実装 | 開口・扉・経路から接続確認 |
| P2 | 保存・復元の改善 | JSONダウンロードのみ | バックアップ/差分確認、再読込一致 |
| 全工程 | PC/スマホ画面QAと回帰テスト | 実ブラウザー未確認 | 主要操作が両環境で確認済み |

## 推奨する実装順

1. **階層を正規化**: 表示LvとparentIdを独立に持ち、旧Scene v2の互換と移行レポートを用意。
2. **重なり解消**: 親の色が子と二重描画されないよう汎用の表示条件を整備。
3. **図形編集を強化**: 施設内部の壁/床/部屋/ポリゴンを直接作成。
4. **扉/開口/接続**: 壁線と扉を紐づけ、通行判定に必要な情報を保存。
5. **フロアと設置物**: 物理階層の切替・階段接続・大型設備/家具配置。
6. **親子移動・編集安全性**: ロック・Undo/Redo・コピー・回転。
7. **検証と公開**: 町サンプル + 既存中層シーンを併用して回帰確認。

## 完成範囲外（将来拡張）

小物の個別管理、装飾、キャラクター配置・行動、3Dや断面立体図は必須としない。詳細は [07](07-floors-and-interiors.md)・[08](08-placeable-objects.md)。

## 中層シーンの既知タスク（データ個別の例）

ユーザー確認済み: `core_shell_refine` は全体区画、内部の4地区がその分割。`core_shell_town`、`refine_valley`、`stern_core_shell_town`、`stern_refine_lab_district` を地区とし、地区の下に施設、その下に室内区画を置く。全体の輪郭、地区ごとの色・座標は変更しない。

- 全体と地区が同じlargeである問題を新階層へ移す。
- 親の環状塗りと4地区の色塗りを重複させない。
- 現在の内部区画A/Bは**仮の小枠**。正式な部屋名・間仕切り・扉を勝手に確定しない。
- 新しい扉・内壁の配置は編集機能を実装してからユーザー指定で進める。

## 完了宣言のルール

**仕様作成 ≠ 機能実装 ≠ 自動テスト通過 ≠ ブラウザー表示確認**。各段階を区別して報告する。既存機能の修正時も、実際に確認した範囲だけを「完了」とする。
