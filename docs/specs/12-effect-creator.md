# Game Creator Tools / エフェクト作成 v1

- 入口: ルート index.html をツール選択画面にする。既存のマップ・名前生成・図形カタログの機能は維持する。全ツールのヘッダーに共通ホームアイコン（shared/tool-home.js / .css）を配置し、確認OK時のみ選択画面に遷移する。キャンセルは現在画面を維持する。自動保存やブラウザーの戻る操作への警告は追加しない。
- effect-creator は独立した静的HTML/CSS/JS。ゲーム本体のデータ、マップデータは編集しない。
- Canvas描画の基本18種類、最大32レイヤー、色/発光/粒子数/乱数シード/位置/角度/サイズ/不透明度/開始終了時点を編集する。各レイヤーは開始終了値の線形補間。すべての描画は固定時間・シードに基づく。
- プレビューと出力は同じ draw 関数。FPS、時間からフレーム数 round(FPS × 秒数) を算出（最低1枚）。フレームiは i/FPS 秒、末尾時点は重複させない。列数0は横一列。
- 背景はプレビューだけ。PNG、WebP、連番PNG ZIP、JSONをダウンロード。WebP未対応時はエラー。シートは最大辺16384px/3200万画素、ZIPは総計1億画素を上限とする。
- コードモードは HTML/CSS/JS の sandbox iframe プレビュー、HTML保存。インラインSVGの対応CSSスタイルを各フレーム時点で固定して画像化する方式と、ユーザー定義の window.renderFrame({canvas,ctx,time,duration,frame,fps}) を各時点で呼ぶCanvas方式を用意。出力形式は共通。SVGの外部画像、foreignObject、SMIL、疑似要素、HTML要素全般、CSSの全プロパティを対象にした忠実なラスタライズは非対応。GIF、WebGL、任意中間キーフレーム、画像レイヤー、既存画像編集/動画/戦闘計算統合は未実装。コードモードの画像出力は実ブラウザー未検証。コードモードのHTMLは信頼できる入力を使用。外部アクセスをCSPで制限し、親オリジンにはアクセス不可。無限ループ等の負荷制限はない。
- 静的サイトのため書き出しとGitHub反映は別工程。
- テスト: node tools/effect-creator/test.cjs。実ブラウザーでの出力・見た目の検証は別途。

## GLSL部品組み合わせ制作方式（2026-11-27・採用、初版試作実装済み）

ユーザー合意：既存の個別GLSL制作を廃止せず、共通エフェクトを部品として再利用し、魔法固有の時間構成・動き・質感を組み合わせるハイブリッド方式を採用する。全魔法のテンプレート化や一括移行は行わない。以下は新方式の設計・実装計画。初版の実装範囲と未確認事項は本節末尾に明記する。

### 制作方式と互換性

- 今後のエフェクト制作・機能拡張はGLSLに一本化する。GLSL部品制作・部品組み合わせ制作・個別GLSL制作を主機能とする。従来のCanvasおよびHTML/CSS/JSコード制作モードは互換性のため現状維持とし、新規制作・積極的な機能拡張の対象外とする（既存機能の削除は今回行わない）。
- 制作時はMyMapCreaterでGLSLを描画し、完成したエフェクトを透過画像・スプライトシートとして書き出す。ゲーム側は画像をCSSアニメーションで再生する方針とし、GLSLの実行をゲーム側の前提にしない。画像形式、フレーム数、FPS、シート配置は既存出力設定で選択する。発動用・持続用の分離を維持する。ゲーム側の詳細実装は fantasy_Strategy の現行仕様に従う。本決定だけでゲーム本体を変更しない。
- 現行458素材のID、GLSL、制作備考、尺、出力設定、発動/持続の関係、承認済みの見た目を維持する。新方式への移行は魔法ごとに比較・確認してから明示的に切り替える。
- 部品は現行の共通GLSL関数（charge、lfPlume、lfWall、lfVortex、denseBurst、denseSmoke、napalmRollなど）を候補にする。ただし現行関数の引数・描画結果・依存を確認し、必要に応じて抽出用ラッパーを設ける。特殊な演出を無理に細分化しない。
- 共通部品の形・動きと魔法固有の構成を分離する。単なる色替えの量産は不可。部品の追加・個別GLSLとの併用や、特殊魔法の個別制作を許容する。

### 部品ライブラリと構成データ（初期設計）

| 分類 | 部品候補 |
| --- | --- |
| チャージ・収束 | 発光蓄積、圧縮、直線収束、螺旋収束、多方向収束 |
| 飛翔 | 直進弾、放物線弾、追尾弾、落下弾、弾尾 |
| 解放・爆発 | 球状爆発、地表爆発、巻き上がる爆炎、連続爆発 |
| 炎・煙 | 火柱、炎壁、炎環、炎竜巻、残留燃焼、黒煙、地表発生の残留煙 |
| その他 | 熱線、光線、放射、地表/空中衝撃波、火の粉・光粒子・氷片・岩片、亀裂・凍結・隆起 |

- 部品定義：安定した部品IDとバージョン、名称、分類、対応視点、GLSL実装と依存、パラメータ定義（型、初期値、範囲、単位）、初期尺・ループ可否、単体プレビュー用設定。
- 魔法構成：既存魔法IDとは別に構成データを保存できる。素材尺、視点、ループ、シード、複数の部品インスタンス（安定ID、部品ID+固定バージョン、開始/終了秒、位置、サイズ、角度、色、透明度、速度、描画順、固有パラメータ、必要に応じて補間と軌道）を記録する。時間は秒を正本とし、部品内の進行0〜1へ変換する。時間重複は許容する。
- 部品バージョンは固定参照。同じバージョンの描画結果を変える修正は原則禁止。新版は別バージョンとして追加し、使用魔法一覧を表示、選択した魔法のみ明示更新する。旧版が不足する場合は読み込みエラーとし勝手に最新版へ置換しない。
- 同じ部品の複数配置、個別パラメータ、描画順と透過合成を許容する。異なる部品の関数名・uniform名の衝突を防止し、共通依存は重複定義しない。既存のGLSLレイヤー最大6を構成部品数の上限に流用しない。複数部品から一つのGLSLに組み立てる方式を第一候補とし、WebGL制限・負荷を確認して上限や分割描画を決める。現行レイヤー機能は維持。
- 構成データと生成GLSLを区別する。構成保存・再読込・部品バージョン固定・決定的生成を優先し、生成GLSLを個別編集する場合は構成との同期・分離を明示する。既存保存形式の互換性を壊さない。

### 編集画面

- 部品ライブラリ一覧（分類、検索、単体アニメーションプレビュー、追加）。
- タイムライン（秒軸、部品ごとの開始/終了、重なり、選択、並べ替え、複製、削除、再生位置）。選択部品のパラメータ編集と全体プレビューを接続する。
- 部品の時間・位置・色・サイズ・回転・透明度・動きの調整。入力変更で可能な範囲は自動反映し、再生位置を維持。コンパイル失敗時は現行の旧プレビュー保持・診断・出力禁止の仕様を踏襲する。
- 既存の透過PNG/WebP/連番・シート出力、CS参照、魔法選択、自動再生、出力設定保持、発動と持続の分離を引き継ぐ。

### 段階導入と受け入れ基準

1. 独立した部品レジストリ・構成データ・バージョン検証・GLSL生成基盤を作る。ファイル構成・詳細スキーマは現行レンダラーを確認して決定。

3. 既存UIから独立した組み合わせ編集モードとタイムラインを追加し、設定、再生、保存、再読込、出力を接続する。

6. 旧魔法ID・既存生成ソース・メタデータ・保存復元・Canvas/個別GLSL・出力設定の回帰試験を行う。共通部品の新版追加で旧版を参照する構成が変わらないこと、欠落依存・重複シンボル・不正な時間・バージョンを検出できることを確認する。

## 魔法エフェクト共通制作ルール v1.0（2026-11-26・採用）

本節は全属性の新規制作・個別改修に適用する制作基準。従来のLv別制作基準と併用し、過去の制作記録と演出の共通方針が矛盾する場合は本節および最新の個別承認を優先する。ゲームの実行仕様・戦闘性能を変更するものではない。既存素材の一括上書きは行わない。

### 1. 視点と座標

- TOP（真上）：地表の範囲・経路・面を主に描く。画面右が攻撃の進行方向。
- SIDE（横）：高さ・上下運動・奥行きを描く。地表が少し見える準側面を標準とし、下が地面、上が空。厳密な水平視線ではなく、地表の円が楕円として判別できる角度を使用する。
- 術者側は左、対象側は右を標準とする。直進・放射・押し出しは左→右、落下・落雷は上→下、噴出・上昇は下→上。収束は周囲→中心。対象周辺の範囲魔法は素材中央、自己強化・防御は術者中心。個別の説明で方向が定まっている場合はそちらを優先する。
- 横方向に飛翔する物体は従来比で飛翔時間約1/3（弾速約3倍）を制作基準とする。溜めと着弾は個別に維持し、既に高速化済みの素材は重複加速しない。 個別改善済みのCS478水晶片・CS490火山弾はユーザー指定により適用除外。
- 2026-11-28 ユーザー再確認：全属性の発射型（弾・矢・散弾・光線・噴射・前方衝撃波等）は、画面左の術者側で発生・蓄積し、画面右の対象側へ進行・着弾する。形状の先端は右、尾・残光は左に追従。散弾は右方向を中心に広げる。新規制作・既存改修ともに適用し、個別の落下・上昇・収束・範囲発生などは固有方向を維持する。SIDEの水平円は横1:縦0.34、TOPは真円。完成判断前に方向と投影を確認する。
- 1素材の途中でカメラや地表の投影方向を変えない。発動用・持続用も同じ視点と接地位置を用いる。
- TOP向き：地表に沿う凍結・雷網・広域範囲・炎収束・火勢前線・爆燃・新星爆発など。SIDE向き：飛翔・放射、噴火、黒煙を伴う爆炎、旋風、落雷、核爆発など。炎環は固定円周の既存SIDE表現を基準にする。種類名で機械的に決めず個別の現象に合わせる。

### 2. 円・面・体積の投影

- TOPの水平円は真円（横1:縦1）。SIDEの水平円は横長楕円（制作標準は横1:縦0.34、核爆発CS261の採用値）。同じ水平面の輪・地表衝撃波・余波は中心・比率・向きを揃え、拡大・収縮中も保持する。
- 2026-11-28再確認：ゲーム用横視点素材の地表凍結面・魔法陣・接地範囲もこの比率に統一。水平面の模様・亀裂・前線・粒子の接地点も同一投影にする。垂直の光輪・空間の球体や煙は機械的に潰さない。新規・改修時に視点と接地面を確認する。
- 空中の球体、球状の爆炎、垂直な面の円まで一律に潰さない。垂直面、斜めに交差する円、球の周回軌道は、その面の方向に応じて投影する。新星爆発の大小交差波など個別承認済みの構成を維持する。
- 地表衝撃波は爆発中心ではなく地表の接点から広げる。火柱・氷柱・樹木・噴煙は根元から成長し、高さと地表との位置関係を見せる。地表そのものを背景画像として描き込まない。
- 前面・中心・背面の重なり、遮蔽、密度・明暗・透明度・大小の差で奥行きを作る。手前の炎や煙が奥のものを部分的に隠すよう合成する。発光核、外層、周囲の粒子・煙など、現象に必要な層だけを使用する。
- 壁・前線・噴流は太さのある面または流れとして描く。爆炎は球状の膨張に不規則な炎の塊を重ね、細長い放射状の棘や単なる線・円・色ベタの集合にしない。光線・雷・意図された鋭い現象は例外。

### 3. 発動・持続・消滅の分離

- 通常名・通常IDは発動用。空の状態から現象が発生し、形成・蓄積・解放・着弾・減衰へ進む。瞬発魔法は必要な段階だけ短く描き、いきなり完成状態を表示するだけにしない。
- 持続する魔法は発動用を完成状態で終え、別素材「（持続）」／ID末尾 -sustain に接続する。形状・位置・色・サイズ・動きの連続性を確認する。持続素材は完成状態から始まるループとし、溜め・形成・解放を毎回繰り返さない。
- 単発攻撃は最後に透明へ戻す。消滅専用素材は必要な持続魔法だけに追加する制作上の選択肢であり、全件追加を要求しない。消滅専用IDやゲーム側再生仕様は未確定。
- 円環は火や光が円周を走って描く、壁は根元から形成、雲は密度と体積が増す、凍結は接点から伝播するなど、現象に合った形成過程を優先する。単なる全体フェードや拡大は仮の初期版扱いとする。

### 4. 時間変化と迫力

- 既存Lv別制作基準を維持：Lv1〜2も品質・視認性・鋭さを落とさない。Lv3から短い蓄積、Lv4から強い解放の勢い。高Lvほど蓄積と解放の対比、密度、余波を増す。単体・支援・防御・回復に不適切な爆発や広域化を強制しない。
- 運動方向に合わせて模様・粒子・炎尾・煙を動かし、形の拡大縮小だけで流れを代用しない。多段攻撃は先行の爆炎・衝撃波が広がる途中に次の波を重ねてよい。新星爆発CS263は三波の重複を基準例とする。
- 各ピークを明確にし、全尺を通じて同じ強さにしない。素材尺・演出上の弾数・波数は戦闘の射程・範囲・回数・ターン数・威力と別管理。画面揺れはゲーム側の既存威力基準で決定する。
