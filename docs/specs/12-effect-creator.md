# Game Creator Tools / エフェクト作成 v1

- 入口: ルート index.html をツール選択画面にする。既存のマップ・名前生成・図形カタログの機能は維持する。全ツールのヘッダーに共通ホームアイコン（shared/tool-home.js / .css）を配置し、確認OK時のみ選択画面に遷移する。キャンセルは現在画面を維持する。自動保存やブラウザーの戻る操作への警告は追加しない。
- effect-creator は独立した静的HTML/CSS/JS。ゲーム本体のデータ、マップデータは編集しない。
- Canvas描画の基本18種類、最大32レイヤー、色/発光/粒子数/乱数シード/位置/角度/サイズ/不透明度/開始終了時点を編集する。各レイヤーは開始終了値の線形補間。すべての描画は固定時間・シードに基づく。
- プレビューと出力は同じ draw 関数。FPS、時間からフレーム数 round(FPS × 秒数) を算出（最低1枚）。フレームiは i/FPS 秒、末尾時点は重複させない。列数0は横一列。
- 背景はプレビューだけ。PNG、WebP、連番PNG ZIP、JSONをダウンロード。WebP未対応時はエラー。シートは最大辺16384px/3200万画素、ZIPは総計1億画素を上限とする。
- コードモードは HTML/CSS/JS の sandbox iframe プレビュー、HTML保存。インラインSVGの対応CSSスタイルを各フレーム時点で固定して画像化する方式と、ユーザー定義の window.renderFrame({canvas,ctx,time,duration,frame,fps}) を各時点で呼ぶCanvas方式を用意。出力形式は共通。SVGの外部画像、foreignObject、SMIL、疑似要素、HTML要素全般、CSSの全プロパティを対象にした忠実なラスタライズは非対応。GIF、WebGL、任意中間キーフレーム、画像レイヤー、既存画像編集/動画/戦闘計算統合は未実装。コードモードの画像出力は実ブラウザー未検証。コードモードのHTMLは信頼できる入力を使用。外部アクセスをCSPで制限し、親オリジンにはアクセス不可。無限ループ等の負荷制限はない。
- 静的サイトのため書き出しとGitHub反映は別工程。
- テスト: node tools/effect-creator/test.cjs。実ブラウザーでの出力・見た目の検証は別途。

## 魔法Lv別エフェクト制作基準（2026-11-26・採用済み制作方針）

魔法Lv3を短い溜めの開始段階、Lv4を衝撃・揺れるほどの勢いを感じさせる強力な演出の境界とする。Lv1〜2は小規模でも鋭く爽快な動きと属性・現象の明瞭さを保ち、Lv3以上は発動前の蓄積を感じさせ、Lv4以上では解放時の急加速・衝撃・余波によって力の差を表現する。以下の分類名は制作上の目安であり、正式なスキル分類名を新設するものではない。

| 魔法Lv | 制作上の段階 | 演出の目安 |
| --- | --- | --- |
| 1 | 初級 | 小規模で即応性のある鋭い動き、明瞭な発生と消滅 |
| 2 | 基礎 | 属性固有の現象を明瞭に表現、必要に応じた持続 |
| 3 | 中級 | 短い溜め・光粒の収束・脈動などから解放、明瞭な着弾 |
| 4 | 上級 | 明確な溜めと急激な解放、衝撃波・振動・急加速など揺れるほどの勢い |
| 5 | 大魔法 | 複数地点・広範囲の現象、または高密度の強烈な一撃 |
| 6 | 超級 | 大規模な連鎖、自然災害級の迫力 |
| 7 | 最上級 | 圧倒的なエネルギー、神話級の現象 |

- 全属性共通。CSの元の効果説明・データ・取得条件を参照し、現象の意味と用途を維持する。Lv4以上でも支援、持続、防御、単体などの性質に合わない爆発・広域化を強制しない。単体魔法はエネルギー密度・集中・一撃の迫力で差を出す。
- Lv3から短い溜め（収束・膨張・発光の増強等）を意識する。Lv4以上の攻撃魔法は解放時に衝撃または揺れるほどの勢いを表現し、現象に応じて衝撃波・枝状放電・飛散・反動・急加速などを選択する。Lvが上がるほど蓄積と解放の対比、密度、余波を強める。支援・防御・回復・持続魔法は形成時の蓄積や脈動、展開の勢いを用い、不適切な爆発や毎ループの溜めを強制しない。実際の画面揺れは既存の威力基準で制御し、Lv4以上という理由だけで追加しない。
- 発生・集中/蓄積・最大出力/解放・減衰の段階を、魔法の性質に応じて明瞭にする。発動前の溜め、属性固有の複数現象、強弱の変化、衝撃波、残留エネルギーなどを選択的に組み合わせる。持続素材は安定したループを優先する。
- 上位になるほど密度・複雑さ・迫力を高めるが、常時強発光や無意味な大型化を避け、ピークを際立たせる。小さなゲーム表示でも形状と動作が判別でき、対象を過度に隠さないこと。画面外への切れ、透明背景、出力時の再現性、端末負荷も考慮する。
- 制作素材の発光球数、枝数、円環数、見た目の範囲、素材尺は戦闘の攻撃回数・射程・範囲・威力・詠唱時間・ターン数と別管理する。既存の威力倍率、画面揺れ、暗転、ダメージ表示時点、実戦の設定優先順位を変更しない。魔法Lvだけで機械的に実行時の表示を変えない。
- 既存の基本形状・属性装飾・共通再生基盤を再利用する方針を維持する。固有の自然現象を表現する必要がある魔法には個別の制作プリセットを用意してよいが、スキル別の実戦再生処理のハードコードや完成画像の無条件大量複製は行わない。
- 新規制作および個別修正に適用する。既存素材の一括変更は行わず、確認・合意したものから順に調整する。この制作基準の採用は、全魔法の素材更新・ゲーム反映が完了したことを意味しない。

ゲーム用制作基準の正本は [fantasy_Strategyの戦闘エフェクトルール](https://github.com/siev0000/fantasy_Strategy/blob/ui/mobile-responsive-port-20260912/docs/rules/ui/戦闘エフェクトルール.md) とする。本節は制作ツールでの参照用であり、ゲームの仕様・データの編集原本ではない。

## 起動失敗対策

- esm.sh単独依存から、PixiJS・フィルター・Quarks・tsParticlesの固定版ブラウザー配布物（jsDelivr → unpkg、PixiJSは公式CDNも）へ変更。Three.jsは同じ固定版のESMをjsDelivr → unpkg → esm.shで試す。各APIを検査し、読込失敗は診断ログに残す。PixiJSはGlowFilterだけ失敗した場合は基本描画で起動し、差を明示する。
- GLSLは外部ライブラリを使わずネイティブWebGL1を使用。シェーダーのコンパイル・リンク・描画エラーを表示する。他のエンジンとして偽装するフォールバックはしない。
- 起動診断欄（WebGL対応、読込先、成功・失敗、エラー）とコピー操作を追加。実際の端末エラー原因・CDN到達性・ライブラリ起動・描画は未確認。

## GLSL制作モード（雷魔法24種）

- GLSL選択時のみ専用パネルを表示。既存5基本形状に加え、CS由来の雷魔法24種を `lightning-presets.js` の名称・備考・尺・配色に対応させる。各魔法は独立したWebGL1フラグメントシェーダー本文を持つ。制作補助データのみ変更、CS原本とゲーム本体は変更しない。
- 最大6シェーダーレイヤー、順序、表示、位置、角度、倍率、不透明度、開始終了（正規化時刻）、通常/加算/乗算/スクリーン合成。1 WebGLコンテキストで個別描画し、透過2D Canvasへ合成。レイヤー時間に応じてuTime/uProgressを設定し、同じ描画を出力に使用する。
- コード直接編集・コピー。任意の単一 `uniform float name;` の設定を最大16個自動生成。任意の `// @param name default min max step` 注釈で数値範囲指定。共有uniformは既存設定と接続。ノイズ/密度/芯/外光は雷魔法の共通パラメータ。効果によって使用されない項目もある。
- 外部試作JSON保存・読込にコード、レイヤー、数値、備考を含む。旧JSONは基本形状として読み込む。エンジン切替時にページ内設定を保持。コンパイルエラーはレイヤー名付きで表示。WebGL1用コードのみ、任意中間キーフレーム/テクスチャ/複数パス依存は未対応。任意コードのGPU負荷制限はない。
- 検証: `node tools/effect-creator/shader-studio.test.cjs`。実ブラウザーのコンパイルと見た目は別途確認する。
