# 07 フロア・施設内部の制作仕様

状態: **次期実装の仕様（未実装）**。完成目標は「基本 + 大型設備・家具の配置」。

## 独立した3種類の階層

- **マップ階層**: 世界→町→建物など、シーンの切替。
- **表示Lv**: 全体区画→地区→施設→部屋→設備など、同一シーン内の表示詳細度。数値 `displayLevel` を予定し、段階数は固定しない。
- **物理フロア**: B2F/B1F/1F/2F 等。これは詳細度とは独立した上下の場所であり、`displayLevel` には換算しない。

どの種類の施設・マップにもフロアを持てる。地下施設、複層ダンジョン、船内、一般建築にも対応し、名称やIDで処理を分岐しない。

## フロアの要件

1. 任意個数のフロアの作成・削除・複製・並び替え。地下・地上・中二階などをラベルで表現。
2. フロアごとに外形、床高さ (`elevation`)、天井高/階高 (`height`) と表示状態を設定できる。
3. 壁、床、部屋、扉、家具、設備などの所属フロアを明示する。存在しないフロアIDは保存検証でエラー。
4. 現在フロアを単独表示。他フロアは必要時に薄い参照表示（ゴースト）を選択可能。編集中フロア以外の誤選択・誤移動を防ぐ。
5. 階段・エレベーター・スロープはフロア間の接続先を明示し、「移動先を表示」で移動する。上下位置が重なっただけでは接続しない。
6. 吹き抜け・大ホール・格納庫など、複数フロアにまたがる空間/構造物を設定できる。
7. 各階の壁・部屋・設備をまとめて複製するとき、IDの重複を避け、参照を整合させる。
8. フロア内での座標と世界座標/施設基準座標を分離し、施設を動かした際の内部位置を保持できる。
9. まずは**2D平面図**で完成させる。3D描画・断面立体図は初期範囲に含めない。

## 次期データモデル（例。キー名は実装前に確定）

```json
{
  "id": "facility-a",
  "objectType": "facility",
  "displayLevel": 3,
  "floors": [
    {"id": "B1", "label": "地下1階", "elevation": -4, "height": 4},
    {"id": "1F", "label": "1階", "elevation": 0, "height": 5},
    {"id": "2F", "label": "2階", "elevation": 5, "height": 4}
  ]
}
```

部屋・壁・扉・設備側の `floorId` は対象のフロアを参照する。複数階にまたがる設置物は明示的な複数フロア参照、または高さ範囲を使う。形式は別途スキーマ移行時に確定。

## フロア編集の最小受け入れ条件

- 地下1階・1階・2階を作成し、切替ごとにその階の部屋だけ表示できる。
- 各階で異なる床/部屋の外形を描け、扉・壁を設置できる。
- 階段を1Fと2Fに接続し、行き先を表示できる。
- フロア複製時に既存フロアや他の施設が壊れない。
- 保存・再読み込み後、所属フロア・高さ・表示が一致する。
