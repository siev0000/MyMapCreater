# 05 データ形式・保存・移行・検証

## 現行ファイルの責務

| パス | データ |
|---|---|
| `rebuild/map-tree.json` | マップ・シーンの親子/参照 |
| `rebuild/scenes/*.scene.json` | 描画・編集するシーン正本 |
| `data/*-layout-draft.json` | 保護すべき既存の元配置 |
| `rebuild/SCENE_FORMAT_v2.md` | 現行Scene v2形式 |
| `docs/specs/*.md` | 現行と次期目標を分離した仕様 |

## 次期スキーマ移行

Scene v2の `level` と、次期 `displayLevel` は意味が違う。既存データを一気に機械置換しない。各シーンの親子参照を照合して移行し、旧データの読み込み互換を期間限定で維持する。

**次期形式は設計段階**。スキーマ番号（v3等）は実装・テスト完了後に確定する。目標の例:

```json
{
  "schemaVersion": 2,
  "objects": [
    {
      "id": "room-a",
      "parentId": "building-a",
      "displayLevel": 4,
      "objectType": "room",
      "geometry": {"type": "rect", "x": 10, "y": 10, "width": 20, "height": 15}
    }
  ]
}
```

上は移行案のフィールド例であり、**現在のScene v2バリデータで受け付ける保証はない**。

## 保存

- 現行: エディターからJSONを読み込み・ダウンロード。GitHub Pagesの画面からGitHubへ直接コミットしない。
- 将来: 差分確認、バックアップ、編集済みデータの復元、任意のリポジトリ保存連携を検討。認証情報はJSONに含めない。
- 保存前に構造エラーを検証する。元配置を上書きせず、必要に応じて変換後の別シーンとして保持する。

## 検証するもの

- ID一意、parentIdの存在、親子循環、数値Lvの妥当性
- 形状の座標・半径・頂点個数などの妥当性
- 壁上の扉、開口の寸法、接続先IDの妥当性
- 子施設が親の意図した領域にあるかの**警告**。強制移動・削除はしない
- 旧シーン読込・新スキーマ往復・Undo/Redo・ズーム/パン・選択
- 世界/町のサンプルで固有IDに依存しないこと
- PC/モバイルの実ブラウザーでの表示・タッチ操作（構文検査とは別）

現行コマンド:

```sh
node rebuild/tests/validate-scenes.js
node rebuild/tests/editor-smoke.js
```

これらが通過しても、未追加の次期機能やブラウザー目視まで保証するものではない。

## 移行時に変更しないもの

既存図形の座標・形・色・レイヤー値、明示された配置、仮定義の状態、元配置JSON。重複表示は表示ルール・透明度と階層を先に修正し、地形の作り直しを避ける。
