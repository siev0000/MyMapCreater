# 実在地域｜咲花駅周辺500m マップ（データ取得・高さ）

更新日：2026-11-09

## 確定済みの仕様

- マップID：`sakihana_gosen_500m`
- 初期シーン：`rebuild/scenes/sakihana-starter.scene.json`
- 座標基準：咲花駅（37.7351639°N, 139.2909028°E）。中心を(0,0)として東向きを+X、南向きを+Y。
- 範囲：東西500m・南北500m。1m=マップ座標4、1マス=50cm=マップ座標2。表示範囲はX/Yとも-1000〜1000。
- **実在地物の推測描画は禁止**。初期シーンには地理座標の基準点のみ。道路・線路・建物・土地利用はユーザーが「咲花OSM取込」を実行した際に、OpenStreetMapからオンライン取得する。
- 標高データは国土地理院のDEM PNGを別取得し、25mピッチで最大400個の編集可能な矩形セルに変換、標高の高低差を色で表示。標高値の欠測・取得失敗時に乱数や想定値を補填しない。
- 実地図を読み込んだ後は既存のJSON保存機能で**固定データのスナップショット**をダウンロードできる。既存の標準シーンやテンプレートは変更しない。
- 既存の汎用マップと現代住宅テンプレート46件は維持。

## 手順

1. `rebuild/editor.html#sakihana_gosen_500m` を開く。
2. マップ一覧から「実在地域｜咲花駅周辺（500m）」を選択する。初期表示は駅の基準点のみ。
3. **咲花OSM取込** を押す。Overpass APIが道路・線路・建物輪郭・自然・土地利用を取得し、緯度経度をマップ座標へ変換する。
4. **標高DEM取込** を押す。国土地理院のDEM PNGが取れた場合に限り、地形セルと標高範囲を表示する。
5. 図形を選択し、座標・形状・標高（m）・建物高さ（m）を編集する。未取得の高さは空欄。手入力値には `manualElevationEdit` または `manualHeightEdit` を付け、DEMの直接測定値と区別する。
6. マップJSONを保存して静的スナップショットを確保する。GitHubへの保存済みシーン置換は別途ファイル更新が必要。

閲覧専用の `rebuild/header.html#sakihana_gosen_500m` にもOSM/DEMの取得操作を追加。編集・保存はエディターで行う。

## 地理情報の出典と許諾

- **駅座標の参考**：咲花駅の位置資料 https://www.rosenzu.net/東北/ＪＲ磐越西線（郡山〜新津）
- **道路・鉄道・建物・土地利用・水域**：© OpenStreetMap contributors。データはODbL 1.0（https://www.openstreetmap.org/copyright）。
- 取得先：Overpass API（https://overpass-api.de/api/interpreter、障害時 https://overpass.private.coffee/api/interpreter へフォールバック）。出力にOSM way/nodeの識別子とリンクを保存する。
- **標高**：国土地理院「基盤地図情報数値標高モデル」の標高PNGタイル。 https://maps.gsi.go.jp/development/demtile.html 、利用規約 https://maps.gsi.go.jp/help/use.html
- 画面右下にOSM/ODbL表示。DEM反映時は国土地理院の出典・リンクも表示。地理院のタイルは本ツールで色別表示へ加工している。
- `settings.georeference` にデータ取得日時・OSM更新時刻・DEMの利用タイル系列・標高範囲・サンプル数を保存する。

## データ変換仕様

- 500m四方を小範囲ローカル平面近似で変換（Xは経度差×111320×cos(基準緯度)×4、Yは緯度差×-111132.92×4）。測量用途の投影ではないためcm級の精度保証なし。
- OSMのwayはタグで道路・鉄道・建物・森林・農地・緑地・水域等に分類し、500m枠でポリライン分割／ポリゴンクリップを実施。各図形の頂点は編集可能。
- 道路・鉄道・水路の描画幅は、タグの`width`がなければ表示専用の推定値（`metadata.renderWidthEstimated=true`）。**幅の推定は実測幅として扱わない**。
- 建物の`height`タグが数値なら`metadata.heightM`として保持、`building:levels`のみなら階数を保持。タグがない建物の高さは未取得。
- DEM PNGのR,G,BからGSI公式仕様に従い実標高を復号（0.01m単位、128/0/0は欠測）。5m系列を優先し、取れない場合は10m系列。標高のある25mセルのみ出力。
- Terrainは数値標高をもつ色付きセルであり、3Dの地形メッシュ・法面・擁壁の実高度を再現するものではない。

## 未対応・未確認

- **未確認**：こちらの作業環境からOverpass / 地理院DEMへのライブ通信ができないため、現時点で咲花駅の実OSM地物数・標高最小最大・オンラインCORS動作は検証できていない。初期GitHubシーンを「実データ取得済み」と呼ばないこと。
- **未対応**：OSM複合リレーション、ポリゴンの穴、タグのない道路・建物、航空写真との比較、駅構造の立体形状、橋・トンネル等のZ方向レイヤー、3D地形、実測の建物高さ。
- 陰影着色は標高の相対差を見分けるための2D表示。高さによって建物を自動移動したり立体変形したりしない。
- 標高データに欠測領域がある場合、セル全域の平均値ではないため厳密な地形解析に用いない。
- 完全な実在地域の再現を保証するには、取得後にOSM内容の現況、道路幅、施設位置、橋、地形モデルを現地資料で確認する。

## 回帰テスト

`node rebuild/tests/sakihana-geodata.js` で地理座標の往復、道路・線路・建物・森林の試験図形の切り出し、シーンバリデーション、400標高セルの生成、GSI RGB復号をテスト。**試験図形は検証専用で実在の咲花地物としてGitHubシーンに含まない。**

## Overpass HTTP 502対策（2026-11-09）

- Overpassの混雑時に`HTTP 502`が返ることがあるため、取得順を `overpass.private.coffee` → `lz4.overpass-api.de` → `overpass-api.de` に変更した。
- 各サーバーのHTTPエラーを収集し、すべて失敗した場合にサーバー別エラーを表示する。各リクエストは利用可能な環境では60秒で中止。短時間の同一サーバー連続リトライは行わない。
- 成功した取得先を`settings.georeference.overpassEndpoint`に保持。既存シーンへの変更は、データ取得と変換が完全に成功した後だけ行う。
- `node rebuild/tests/sakihana-overpass-failover.js`を追加。模擬的なHTTP 502→代替サーバー成功、および全サーバー失敗時の診断表示を検査。
- 利用者側のブラウザー実通信成功は未検証。公開サーバーの空き状況やブラウザーのCORS設定によって失敗する可能性は残る。

## 確認画面からの保存・編集引き継ぎ（2026-11-09）

- 確認画面 `header.html` の咲花駅マップに「取得結果をJSON保存」「取得結果を編集へ」のボタンを追加。OSM地物・DEM地形のいずれかの取得成功後に有効化する。初期の駅基準点のみでは保存可能な実測地物がないため無効。
- **JSON保存**：確認画面で取得した`schemaVersion:2`のシーン全体を `sakihana_gosen_500m.scene.json` としてブラウザーダウンロードする。既存保存形式を変更しない。
- **編集へ**：現在の地図を`sessionStorage`の`mymapcreater:viewer-to-editor:sakihana:v1`に一時格納し、同じタブで`editor.html#sakihana_gosen_500m`に遷移。編集画面は駅の標準シーンを読み込んだ後、引き継いだシーンを検証して表示し、成功時に転送データを削除する。失敗時は転送データを保持し、エラーを表示する。
- 引き継ぎはブラウザーの同一タブ・同一オリジンでの`sessionStorage`を使用。容量制限等で転送できない場合はJSONダウンロードを案内する。
- **注意：JSONをブラウザーで保存してもGitHubの静的シーンファイルは更新されない**。再訪時に初期シーンが表示される。公開マップの既定状態を固定するには、ダウンロードしたJSONを`rebuild/scenes/sakihana-starter.scene.json`などのGitHub側ファイルに別途反映する必要がある。
- 実際の通信成功とブラウザーでの一時転送は未検証。コードの構文とシーン形式について検証済み。

## 共通地域インポートへ移行（2026-11-09）

**目的の修正（確定）**：MyMapCreater はマップ制作・編集が主機能。OSM/DEM取り込みは任意の実在地域の編集用下地を用意する**補助ツール**とし、咲花駅専用の基本操作から分離した。

### 新しい利用手順
1. `rebuild/editor.html` の **「地図データ取込」** を押してパネルを開く。マップ作成に不要な場合は閉じておける。
2. 地名・駅名・住所を入力して **「地名を検索」**、候補を選択する。または緯度・経度を直接指定する。
3. 250/500/1000/2000m四方の範囲を選び **「指定地域の地図を取得」**。
4. OSMの図形をすべて通常の編集可能なScene v2オブジェクトとして読み込む。元マップや他地域の標高を勝手に合体させない。
5. **「現在の地域の標高を取得」** で、そのマップと同じ中心・範囲のDEMを読み込む。
6. 作業対象の選択欄で地形・標高、建物・施設、道路、鉄道、河川・水域、その他を切り替える。地形セルが多数ある場合も目的の図形を探しやすい。
7. 編集後は **「街マップJSONを保存」** でファイルとして保存。GitHubの標準シーンには自動反映しない。

### 構成・互換性
- 現在の共通実装は `rebuild/geo-data-import.js`。既存の`rebuild/sakihana-map.js`は以前の利用形態との互換性のため残す。両モジュールの関数群は同等で、共通モジュールは`window.AAMapGeoImporter`（および従来の`window.AASakihanaMap`）を公開。
- 咲花駅の固定マップID`sakihana_gosen_500m`、`rebuild/map-tree.json`、`rebuild/scenes/sakihana-starter.scene.json`を変更しない。ユーザー取得済みの488オブジェクトを含むJSONも引き続き読み込み可能。
- 任意地域の新規マップIDは、地理中心座標と一辺長から生成する。`geo_<緯度>_<経度>_<サイズ>m`形式。編集セッション中は選択欄に「制作中」として残るが、永続化にはJSON保存が必要。
- `rebuild/header.html` は原則閲覧用に戻し、閲覧画面内の咲花駅固有OSM/DEMボタンを撤去。**「地図データ取込（編集画面）」** リンクから共通取込パネルを開く。
- 既存Scene v2のオブジェクトを変えない。カテゴリは`metadata.featureKind`と`layer`で区別し、既存`facility`や`route`もフィルタに含める。
- 検索は公開Nominatimを**明示的なボタンクリック**でのみ1回実行する。入力中の自動補完なし。短時間での再検索を制限。公開Nominatimの利用規約 https://operations.osmfoundation.org/policies/nominatim/ に注意し、利用規模が増える場合は自前の検索基盤または別プロバイダーへ移行する。
- OSM線幅で`metadata.renderWidthEstimated=true`の場合はあくまで表示用推定値。取得できない図形や高度を推測して事実として生成しない。DEMの標高は実値から作った20×20セルの平均（セルサイズは取得辺長/20）。
- 全46種類の既存建物テンプレートを改めてScene v2形式で検証。共通地理取込では中心・範囲変更3例とDEM400セルの生成・地名検索モックを検査。
- **未確認**：公開OSM/Nominatim/GSIへの実ブラウザー通信、UIの視認性、GitHub Pagesへのキャッシュ反映。現時点では標高セルは400件の編集可能な矩形であり、地形メッシュ/等高線/地形ブラシへの統合は次段階。

## 町制作向け編集機能の追加（2026-11-09）

新しい`rebuild/town-edit-tools.js`は地理データ取得から独立した**町制作用**モジュール。咲花駅に限らず、`metadata.featureKind`に道路・地形が記録されたScene v2で利用可能。

### 道路の接続
- 道路を選び、`最大接続距離`（0.1〜20m）内の別道路の端点を検索。
- 最短の端点同士を中点で一致させ、2本を接続する。OSMの元のIDやタグは維持し、`manualGeometryEdit:true`を付ける。
- **未対応**：道路途中での交差点分割、橋の上下分離、道路の通行ネットワーク生成。交差する道路を自動接続したものとして誤認しない。

### 標高の範囲編集
- 編集する地形セルを選択し、中心から半径0〜500mの地形セルに、指定した標高変化（-100〜+100m）を適用。
- 変更後の標高は`metadata.elevationM`に保存。地形セルの着色を更新し、`manualElevationEdit:true`と`verifiedElevation:false`で変更前のDEM由来値と区別。
- **未対応**：セル境界の滑らかな斜面補間、法面・崖の実体、道路や建物の高さの自動追従、元DEM格子の保持。

### 建物配置
- 従来の建物テンプレート一括配置に「選択図形の中心から配置」オプションを追加。
- OSM建物輪郭を選択した場合も位置の目安に利用できるが、輪郭を変換・上書きするのではなく、その位置へ**別の建物テンプレートを置く**。
- 選択したOSM建物は`region`/`facility`ではないため、親子関係の親にはせず配置アンカーのみとして扱う。
- **未対応**：任意の実在輪郭とテンプレートを自動一致させる変形、衝突回避、自動密集配置。

### データ安全性
- 編集操作は新しいScene v2のコピーに対して実行し、既存の`applyScene`によって履歴（戻す・進める）へ記録する。
- 元のアップロードJSONやGitHubに保存した咲花駅スターター、既存46件の建物テンプレートは改変しない。
- 編集した町は`街マップJSONを保存`からブラウザーダウンロードする。GitHub上の初期シーンへの自動反映は行わない。
- 回帰テスト`rebuild/tests/town-edit-tools.js`を追加。模擬道路端点の接続、距離制限、地形セル範囲編集、標高変更の出典属性、元シーン不変を検証。既存46テンプレートの生成も検証。
- **未確認**：ユーザーのブラウザー操作による動作テスト、OSM生データの道路接続の現実妥当性。
