# 02 表示Lv・親子関係・選択表示

## 問題

従来の `level: "large" / "medium" / "small"` は段階が不足していたため、**主要シーンJSONとサンプルを `displayLevel` の整数へ移行済み**。意味は `objectType` で管理する。区画同士の重ね塗り解消は別タスク。

## データ形式（現行の移行済みシーンで使用）

```json
{
  "id": "district-a",
  "name": "地区A",
  "objectType": "region",
  "displayLevel": 2,
  "parentId": "complex-a",
  "geometry": {"type": "polygon", "points": [[0,0],[100,0],[100,100],[0,100]]},
  "visible": true,
  "selectable": true
}
```

- `displayLevel`: 1以上の整数。**上限なし**。同じLvに複数オブジェクト可。
- `parentId`: 同一シーン内の親IDか `null`。必ず実在する対象を参照する。循環禁止。
- `objectType`: 自由な文字列で種類を示す（region/facility/room/wall/door/route等）。
- `zIndex`: 純粋に描画順。Lvより高い・低いことを示さない。
- `visible` と `visibility`: 表示条件。`selectable` は通常選択の可否。
- 深さとLvを一致させることを**標準**とするが、移行では不整合を検出し、自動で親やLvを推測しない。

## 施設内部までの代表例（階層数固定ではない）

| displayLevel | 例 |
|---|---|
| 1 | 全体区画 |
| 2 | 地区 |
| 3 | 施設・建物 |
| 4 | 部屋・内部区画 |
| 5 | 室内設備・細部 |
| 6以降 | 必要なら任意の追加階層 |

壁・扉・道・注記は任意の親と表示Lvに属せる。意味と表示深さは独立。

## 初期表示Lvと選択による展開（実装済みの基本動作）

- 各Scene v2の `settings.initialDisplayLevel` に、初期表示する最大Lvを1以上の整数で指定する。未指定時は3。
- 今回の5シーンは `"initialDisplayLevel": 3` を使用。未選択時はLv1〜3まで表示し、Lv4以上は非表示。
- Lv3の施設を選択すると直下のLv4（部屋・内部区画）を表示。Lv4を選択すると直下のLv5（設備など）を表示する。孫以下を無条件に重ねない。
- ツリーメニューも設定値の手前までを初期展開し、Lv3の項目がすぐ選べる。選択・展開でさらに下位を開く。
- `displayLevel` は詳細度、`floorId` は物理階の指定であり、混用しない。同じ区画の1F/2Fはその階に属する内容物だけ表示する。
- 旧 `visibility.whenParentSelected` は、数値Lvを持たない古いデータ向けの互換判定とし、新仕様は `initialDisplayLevel` に従う。

```json
{
  "settings": {
    "initialDisplayLevel": 3
  }
}
```

## 内部への移動方式（実装済み）

- 地図の初期表示は `settings.initialDisplayLevel` 以下を使用。選択するだけで全下位図形を重ねる方式は廃止。
- 施設などの親を選択したら、フッターの「内部へ入る →」で、その親区画と**直下の子だけ**を表示する専用ビューへ移動。
- 下位の区画をさらに選んで「内部へ入る →」とすると、その区画の平面図に入る。余分な周辺施設は描画しない。
- 「← 上の階層へ」で一段階戻る。内部表示中は地図上部に現在の親子経路（パンくず）を表示。
- 1階・2階等の物理フロア切替は内部への移動とは独立。選択した階に属する小物のみを表示する。
- ツリーから内部施設を選ぶ場合や直接リンクを開く場合は、対応する内部ビューに直接入る。
- 小物のラベルは個別の `label.visible` で制御でき、テスト小物6件は地図上では名称を隠し、フッターだけに名称・説明を表示する。

## 表示動作

1. 初期画面: シーンが定めた初期表示Lv以下だけを表示する。
2. 親を選択して「内部へ入る」を押す: 親の区画とその**直接の子**だけを独立した表示にする。孫以下は非表示。
3. 子を選択して「内部へ入る」を押す: 子の独立ビューに進み、その直下の内容を表示する。
4. 戻る操作: 一段上の親ビューへ戻る（再び元の階層の平面図を表示）。
5. 展開における塗り: 親と子の塗りの多重重ねを避けるため、親の塗りを抑える/表示しない等の**汎用JSON設定**を設ける。輪郭は保持可能。
6. ラベル: 対象の `label.visible=false` を厳守。Lv別の表示規則もJSONに持たせる。地図名による強制表示をしない。
7. `selectable:false` の外殻/背景は通常クリックを占有しない。編集パネルでは一覧から選択して修正可能。
8. ズームは表示範囲を変えるだけで、子階層を勝手に開かない。

## ツリーUI

現在のシーンのルートから**親子関係を再帰的に列挙**する。固定の「大枠/中枠」だけを出す処理を廃止。名前がなくてもIDで操作でき、同名でもIDで区別。子なし行は末端。階層へのジャンプは選択オブジェクトの祖先経路を展開する。

## 移行規則

- 旧 `level` は変換の参照に使うが、文字列によって固定の番号を自動割り当てしない。親子構造を検証して移行表を作る。
- 既存5シーンとサンプルでは旧 `level` を削除し、整数 `displayLevel` を保存。旧JSONを読み込む場合の互換処理は必要に応じて残す。
- 既存の `parentId` を保護し、明示的に確認された親子関係だけ更新する。
- 既存の座標・描画スタイル・施設寸法は移行で変更しない。

## 確認済み配置上の課題（特定シーンの事例でありエンジン規則ではない）

中層シーンでは「コアシェル・リファイン」が**全体区画**で、その内部を船首/船尾のタウン・ラボの4地区に分ける。ユーザー確認済みの関係:

- 全体: `core_shell_refine`
- 4地区: `core_shell_town`, `refine_valley`, `stern_core_shell_town`, `stern_refine_lab_district`
- 4地区の施設は、その地区の子。施設内の小区画はさらにその施設の子。

全体区画をLv1、その下の4地区をLv2、地区内の施設をLv3、内部区画をLv4へ移行済み。元の輪郭・位置・色は変更していない。**親子で重なる塗りの表示制御は引き続き未対応**。環状領域と各地区が意図的に面積を共有する点は、地理の重なりと表示上の重ね塗りを区別すること。
