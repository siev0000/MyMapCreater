# 08 設置物・家具・大型設備の配置仕様

状態: **次期実装の仕様（未実装）**。ユーザー確定の完成範囲: **基本的な施設内部 + 大型設備・家具などを配置できるまで**。

## 初期完成範囲

- 部屋/フロアの上に、大型機械、タンク、制御盤、作業台、机、椅子、棚、ベッド、カウンター、コンテナ等を配置する。
- 物の種類ごとに固有の描画コードを作らず、**共通オブジェクト配置エンジン**で扱う。
- 細かな装飾品、1個単位の小物、キャラクター・NPCの管理/移動、3D家具モデルは**初期完成範囲外**。後から増やせるデータ構造にする。

## 各設置物に必要な情報

| 属性 | 説明 |
|---|---|
| `id`, `name` | 固有ID、名称 |
| `objectType` / subtype | 設置物の種類。固定家具、設備、移動可能な物などをデータで分類 |
| `parentId` | 部屋・施設などの親 |
| `floorId` | 所属する物理フロア |
| `displayLevel` | 詳細表示Lv。階数と混同しない |
| `geometry` | 矩形・多角形・円等の占有外形 |
| 位置、幅、高さ、角度 | 位置・大きさ・向き。親基準の座標を将来サポート |
| `style` / assetRef | 色/輪郭、またはアイコン・画像素材の参照 |
| `visible` / locked | 表示・非表示、編集ロック |
| `blocking` | 通行障害として扱うか。見た目で自動判断しない |
| `metadata` | 説明、材質、用途などの拡張属性 |

具体的な追加キーの正式名はスキーマ設計時に確定する。

## 必須編集操作

1. 矩形、円、ポリゴン等の簡易図形をそのまま設置物として利用できる。
2. 設置物を選択し、移動・拡縮・回転・複製・削除できる。
3. 設置先のフロア・部屋を指定する。親施設の移動に内部設置物が追従する。
4. 配置の精度を上げるスナップ（グリッド/壁/頂点）をON/OFFできる。
5. 同種設置物をまとめて複製、複数選択、整列できる。
6. 種別ごとに表示/非表示を切替え、必要ならロックできる。
7. 追加素材は外部アセット/URL/データ参照で管理し、特定世界設定の素材をエンジンに埋め込まない。
8. JSONの保存→再読み込みで位置・角度・外形・画像参照・所属階が一致する。

## 初期範囲と次期以降

**初期必須**: シンプルな2D設置物、共通配置、フロア関連付け、移動/回転/複製、サイズ変更、グループ/整列、任意の通行障害フラグ、JSON保存。

**後回し**: 家具ごとの専用UIや動作シミュレーション、細かな小物・装飾、人物/ロボットの配置・アニメーション、照明シミュレーション、3D表示。

設置物は床・壁・扉の代用にはならず、区画境界から自動生成しない。異なる役割はオブジェクトとして分離する。

## 文字アイコン＋図形の組み合わせ（採用する次期仕様）

**図形と文字アイコンは排他ではなく、同一設置物に両方設定できる。**
外形・占有面積は図形が担当し、種類の識別は図形の上に重ねた文字アイコンが担当する。文字アイコンなし、図形のみ、両方、必要時の画像素材への置換も認める。

- 図形：矩形・円形・多角形等。実際の設置範囲、当たり判定の基準、選択・回転・拡縮の対象。
- アイコン：文字・Unicode記号・絵文字（例：⚡、🔧、📦）。図形の中央等、指定した相対位置へ重ねて表示。アイコン自体から当たり判定や通行制限を推測しない。
- 名前：アイコンとは別のラベル。`label.visible` によって表示を切替えられる。
- 色・フォント・文字サイズ・アイコン位置・図形の透明度は独立に指定できる。
- OS差の大きいカラー絵文字は見た目の再現性が保証されない。向き・開口・障害の位置などは図形で表現する。

### 変数として登録するプリセット

**同じ組み合わせを毎回設定せず、共通のプリセット定義から選択して配置する。**

- プリセットには `id`、表示名、基本図形、初期寸法、色、文字アイコン、アイコン位置・サイズ、回転時の表示方針、初期の通行障害設定を持たせる。
- 地図上の設置物にはプリセットを参照する `presetId` と、個々の位置・階・親・IDだけを保存する。必要な項目のみ個別上書きを許す。
- プリセット内容を変更したときに既存の設置物へ自動反映するかは、**プリセット連動 / 配置時に固定**を指定できるようにする。既存オブジェクトを意図せず変更しない。
- ユーザーが新しいプリセットを追加・編集・複製・削除できる。削除時には参照中の設置物を警告し、表示を勝手に失わせない。
- アプリ内のプリセット一覧で、図形とアイコンの両方を表示するプレビュー・カテゴリー検索を提供する。
- プリセットのデータは将来、シーンの内部か共有カタログJSONとして管理する。正式な保存場所・フィールド名はスキーマ実装時に確定する。

### データ例（設計例・現在のScene v2では未実装）

```json
{
  "presets": {
    "power_unit": {
      "name": "電源設備",
      "objectType": "equipment",
      "geometry": { "type": "rect", "width": 80, "height": 50 },
      "style": { "fill": "#355967", "stroke": "#9edbe6" },
      "icon": { "text": "⚡", "position": "center", "fontSize": 20 },
      "blocking": true
    }
  },
  "objects": [
    {
      "id": "power-unit-01",
      "presetId": "power_unit",
      "parentId": "equipment-room",
      "floorId": "1F",
      "position": [120, 60],
      "rotation": 0
    }
  ]
}
```

プリセットと個別配置の合成は読み込み時に行う。個別値とプリセット値の優先順位を定義し、保存・読込で結果を一致させる。上の例は仕様を説明するもので、既存シーンへ直接投入するJSONではない。

### 初期のプリセット候補

| プリセット名 | 図形 | 文字アイコン |
|---|---|---|
| 発電機・電源設備 | 矩形 | ⚡ |
| 整備機械・作業台 | 矩形 | 🔧 |
| 保管コンテナ | 矩形 | 📦 |
| 制御端末 | 小さな矩形 | 💻 |
| タンク | 円形/楕円相当 | 任意 |
| ベッド | 矩形 | 任意 |
| 机・棚 | 矩形 | 任意 |

これらは**編集用の初期候補**であり、設置物種類を固定するリストではない。アイコンも図形もユーザーが自由に変更できる。

### 受け入れ条件

1. プリセットから「矩形＋⚡」を選び、任意の部屋・フロアへ配置できる。
2. 同じプリセットを複数配置し、位置・角度・寸法を個別に変更できる。
3. アイコンの表示ON/OFF、サイズ・色・位置の変更が図形の占有範囲を変えない。
4. プリセット参照を維持した保存→再読み込みで図形・文字アイコンが一致する。
5. 図形の当たり判定とアイコンの装飾描画を分離できる。
