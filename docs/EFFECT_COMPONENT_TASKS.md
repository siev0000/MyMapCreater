- EFX-ID順を基本に、前提タスクが完了した後に次へ進む。検証環境の不足は「保留・未確認」として扱い、完了としない。独立した準備を並行する場合は明記する。
- 各タスクに変更ファイル、コミット、実施した試験、未確認・残課題を記録し、HANDOFF.mdと矛盾しないように更新。
- 「実装済み」「モデル試験済み」「実WebGL確認済み」「ユーザー目視承認済み」を分ける。
- 新規開発はGLSL。ゲーム側は透過スプライトシートをCSSで再生する方針。既存458素材と個別GLSL・旧制作機能を保護。ゲーム本体・CS原本を無断変更しない。

- 仕様書の共通制作ルール（TOP/SIDE・方向・透過・発動持続分離・Lv別品質）を守る。
