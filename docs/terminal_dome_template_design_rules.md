# リンクターミナル・レジストリンク・ドーム｜テンプレート制作・接続設計ルール
更新日：2026-11-12
状態：確定要件と試作実装を分離して管理

## 確定要件（ユーザー指示）
- まず建物テンプレートを作成・編集し、完成後に中層シーンへ追加する。中層シーンに先行して内部オブジェクトを直書きしない。
- 直径500mの既存中央ターミナル外形を維持する。
- 中央構造柱の周囲に左上・右上・左下・右下の4群の昇降機を配置。各群に一般用1基・大型用1基、計8基。
- リンクターミナルは昇降機から到着した個体向けで、昇降機側を向いた案内・受付。
- レジストリンク・ドームは外側から到着した個体向けで、外周側を向いた広めの分散受付。非常に多数の来訪を想定。
- 施設間の連絡通路のみ通行許可制。警備担当個体は通行可。通常の施設入口にこの施設間許可を要求しない。
- 一般個体用と大型機・貨物用の通路を分ける。
- 昇降機本体から実際に扉を通って移動できる構造を設計する。

## 実装時の必須手順
1. **新規**テンプレート `machine_mid_link_terminal_dome_v2` を編集し、専用の編集プレビューで確認する。**旧試作** `machine_mid_registlink_dome` は参照用に保持し、明示許可なしに変更しない。
2. 昇降機ごとに「昇降路（シャフト）→実際の開口部・扉→乗降ホール→通路→案内・受付／倉庫」をつなぐ。扉は単なる線の装飾にせず、通行可能な開口と対応づける。
3. 一般用・大型貨物用の扉幅、必要通路幅、壁と開口の関係をそれぞれ設計し、通路同士が不用意に交差しないようにする。
4. 壁は開口位置で分割する。壁を横断する通路、壁の内側に閉じ込められた部屋、扉のない昇降機を残さない。
5. レジストリンク・ドームの外周側入口→分散受付→待機・任務管理区画の経路を確保する。受付の正面を内側に向けない。
6. リンクターミナルとドームの施設間連絡部には許可確認を設ける。警備通行権限を区別する。通常入口は自由利用とする。
7. 部屋・倉庫・会議室・検査・危険物隔離の各経路を確認する。貨物／大型機経路と一般個体経路を混在させない。
8. 最終確認：全昇降機から通路へ到達可能か、全受付へ外周から到達可能か、全施設間経路が認証部を通るか、各部屋に扉があるか、閉塞・重複・衝突がないかをテストする。
9. **通行可能性をコードとプレビューで確認できるまで完成扱いにしない**。確認後にテンプレートから中層へ配置する。

## 新規版の作成方針と実装状況（2026-11-13）

### 固定方針・確定要件
- **編集対象は新規版のみ**：`machine_mid_link_terminal_dome_v2`（生成器 `generateTerminalDomeV2`）。`machine_mid_registlink_dome`（`generateRegistlinkDome`）は比較用の旧試作として凍結する。旧試作の修正はユーザーの明示指示を要する。
- **中層本体は触らない**：`rebuild/scenes/middle.scene.json` に仮生成物を追加・自動反映しない。先にテンプレートを完成・検証する。
- **正本はNotion**：施設の機能・進入方向・許可範囲は[リンクターミナル](https://www.notion.so/1defa1b30dc980e69522e981b7a58e73)と[レジストリンク・ドーム](https://www.notion.so/1defa1b30dc9808f857ccbc8f17ef5b9)、[中層](https://www.notion.so/1ddfa1b30dc980558483cc7f35fab676)を優先。寸法・座標の仮値を確定設定と混同しない。
- **同心円の中央施設**：外径500mを維持。中央柱の周囲の斜め4群に各一般用1基・大型機/貨物用1基、合計8基。扉は外周向き。
- **昇降機の正しい接続**：昇降機を待機帯の境界へ寄せ、8基とも「昇降機側・一般案内待機帯」の**内周壁（現在の試作半径57m）に出口を接する**。境界壁は扉位置で切断して開口を確保。道路を昇降機へ無理に引き寄せる設計で代用しない。
- **短い乗降通路**：出入口直後の通路は1〜2マス程度（現試作は公称2マス＝1m）。一般用と大型用で必要な有効幅を区別する。
- **一般と大型機・貨物は動線分離**。大型用道路は線の `strokeWidth` を実寸扱いせず、**世界座標で幅を持つ面**として作る。外周出入口まで接続する。歩行者経路も別に用意する。
- **受付**：狭い独立室ではなく広い共用空間の開放型カウンターを分散配置する。リンクターミナルは昇降機側、ドームは外周来訪側へ向ける。
- **通行許可**：施設間連絡部のみ許可制、警備個体は通行可能。通常の外部入口にその許可を要求しない。

### 実装タスク（順序と完了条件）
- [ ] **P0：表示確認** — 新規テンプレートの全景と中央部拡大図を確認。縮小しても道路が画面を覆わず、扉・部屋・区画境界が読み取れること。
- [ ] **P0：昇降機・壁・待機帯接続** — 8基すべてで昇降機扉→1〜2マスの乗降部→待機帯の内周壁開口が一致すること。壁と扉が重ならず、扉幅が足りていること。
- [ ] **P0：道路の正確な接続と干渉検査** — 大型用各出口から外周の大型搬出入口まで、幅を持つ道路が連続すること。一般歩行者の経路と、壁・試験室・受付の衝突がないこと。
- [ ] **P0：動線と権限検証** — 一般用/大型用のルートを分離し、施設間ゲートのみ認証が必要で、警備は通れることを到達性テストで検証する。
- [ ] **P1：実際に部屋を配置** — 受付は開放空間として保ち、倉庫・会議室・検査・管理など必要施設を用途別に配置。出入口、壁厚、アクセス、角度・半径を確認する。
- [ ] **P1：円環区画と寸法の整理** — ドーム・待機帯・物流帯・施設間境界の重なり、表示順、壁開口、寸法差を調整。特にギルド仮円環130〜244mと従来の130〜210mは**確定済みの変更ではない**。
- [ ] **P2：壁充填エリア機能の検討** — 円/多角形など範囲を構造壁として埋め、内側の部屋・通路を「くり抜く」機能のデータ構造、描画、編集、通行判定を設計する。**提案段階・未実装**であり、既存壁モデルを勝手に置換しない。
- [ ] **P2：受入テストと反映** — 旧テンプレート不変テスト、新規テンプレート生成テスト、扉/通行/衝突テスト、実画面ズーム確認を通した後に、承認を得て中層シーンへ配置する。
