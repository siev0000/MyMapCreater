# AA施設・街区マップ制作統一ルール v1

> 適用対象：AA《アポクリファ＝アーカイブ》の上層・中層・下層マップ、施設外形、道路、施設内部、HTML地図表示。
>
> **今回の制作方針（2026-11-08）**：**大枠を先に決めてから細部を作る**。**GitHubで設計・表示・検証・ユーザー確認まで完結させ、その完成案のみNotionへ反映する**。途中案はNotionに追記しない。
>
> この文書は**GitHub側の制作工程ルール**である。既存Notionに記録済みの世界設定の正本性、共通参照ルール、施設の設定は置き換えない。制作途中の案はGitHubで管理し、ユーザー承認を経てNotionに記載されて初めて現行正式設定に反映する。

## 0. 作業開始前の必須参照

1. プロジェクトファイル `AI用_プロジェクト参照ルール_更新版_2026-09-25_v3.md` を確認する。
2. Notion「制作・参照ルール｜共通」「00｜設定参照索引｜どこを見るか」を確認する。
3. Notionは **「エリア → 対象階層 → 対象施設 → シナリオ上必要な移動経路」** の順に現行ページを取得する。
4. GitHubの `data/upper.json`, `data/middle.json`, `data/lower.json` は比較用のNotion基準配置、`data/*-layout-draft.json` は**未確定の作業案**として区別する。
5. 現行NotionとGitHub案が食い違う場合は差分を記録する。古い案を無断で確定状態に戻したり、推測で穴埋めしない。

## 1. 制作は6段階に分け、逆順で細部を作らない

| 段階 | 決めるもの | ここでは決めないもの | 完了条件 |
| --- | --- | --- | --- |
| **①全体骨格** | 船体形状、構造核、三層共通ターミナル位置、船殻の緩衝帯、階層と大地区、立入制限 | 受付・室内配置・店舗・小通路 | 全体図で階層ごとの役割と地区の配置範囲が読める |
| **②地区・主要施設の外形** | 地区の輪郭、独立施設の位置・寸法・所属関係、地区と個別建物の区別 | 施設内の細かい部屋、窓口、家具 | 施設重複・船殻はみ出し・用途の矛盾がない |
| **③主要交通と区画境界** | 幹線道路、環状路、物流、一般・大型機の通路、出入口、認証門、隔壁、避難経路 | 受付の席数・会議室の間取り | 各施設の出入口が実際に経路へ接続し、通行権限を確認した |
| **④施設内部の大区画** | 施設の中の主な機能区画と内部動線、階層の出入口との接続 | 小部屋・個別受付・端末などの細部 | 機能同士の隣接関係と移動の可否が確認できる |
| **⑤施設内部の詳細** | 受付、小作戦室、管理室、倉庫の各区画、内部通路・扉・シャッターなど | 設定にない新施設の自動追加 | 各詳細が親施設の内側に収まり、接続も矛盾しない |
| **⑥総合検証と反映準備** | 干渉、動線、構造柱、シナリオの移動テスト、三層間整合、画面表示 | 未承認案のNotion書込 | GitHubの完成案と変更一覧をユーザーが確認・承認した |

**重要：①②が未確定の時点では④⑤を確定しない。** ②や③が変更されたら、その影響を受ける④⑤は再検証し、古い内部構造を無条件に引き継がない。細部のアイデアを先に考えた場合も、独立した「未実装・未承認の案」として保留する。

## 2. 大枠を作るときの統一単位

| 単位 | 内容 | マップ上の扱い |
| --- | --- | --- |
| **階層** | 上層・中層・下層 | 全体図上で選択できる |
| **地区・街区** | 生活圏、研究区、工業区、人工自然区。**300～600mは開放街区の目安であり単一建物の寸法ではない** | 用途を表す広がり・大枠で表示 |
| **主要施設** | 中央ターミナル、研究施設、ギルド、ラボ、貨物検査区など | 建物の外形と施設名を表示 |
| **施設内部の大区画** | 乗降区、ギルド区、工房区、管理区など | 親施設を選択して初めて表示 |
| **施設内部の細部** | 受付、小作戦室、倉庫、警備室、個人工房など | 該当する親施設・内部区画の選択時だけ表示 |

- 所属する施設と地区を別々の遠方に置かない。**レジストリンク・ドームは中層リンクターミナル内部**、**アルキメリア装備開発ラボはリファインバレー内**、**コアシェルタウンとリファインバレーは連続した生活圏**というユーザー指定を維持する。
- 地区の大きな枠をそのまま一棟の建物や通行不能な壁として描かない。
- 建物がない場所を即「空き地・建設可能地」と確定しない。道路、支柱、空調、壁内整備帯、避難路、予備余白などを検討する。
- ターミナル塔は**現行初期寸法：中心(0,0)、半径250m、直径500m**を基準とする。外側のコンコースは半径250～330m。改寸する場合は**三層共通構造として同時に検証**する。
- 上層の認証区画、下層の隔離・危険物動線、船首の上層専用出撃区、船殻外周の独立機関区は現行設定と照合する。

## 3. 道路・隔壁・構造物の制作ルール

- **近接していてもつながっているとは限らない。** 道路、内部通路、リフト、ゲートの接続先を登録して初めて通行可能とする。
- 「描画用の仮線」と「通行可能な実経路」は必ず区別する。
- 一般・大型機・重貨物・危険物・生物・整備・非常時の動線は、現行Notionの区分に従って分離する。交差しただけでは乗換可能としない。
- 門と道路の位置が違う、道路が建物に食い込む場合は**警告として残して③へ差し戻し**、直線延長で誤魔化さない。
- 隔壁は必要な封鎖区間、構造柱は構造支持点、施設外壁は建物境界として別レイヤー管理する。
- 市街地の上を機械的に一枚の隔壁で横切らせない。必要に応じて道路・ゲートを残して大枠を作る。
- 出入口・柱・隔壁・建物外形・道路幅（余裕幅も考慮）を統合して検証する。施設外形確定前に柱位置を決定しない。

## 4. HTML地図の表示ルール（共通）

### 通常表示：大枠優先
- 階層の主要施設名、地区の色分け、主要道路、ターミナル外形までを表示する。
- **受付、作戦室、倉庫、端末、内部区画の名前や図形は常時表示しない。**
- 内部の説明が密集して全体配置を隠すのを避ける。ラベルの重なりや不自然な縁取りも表示検証の対象とする。

### 施設を選択したとき
1. **ターミナルを選択**：ターミナル内の「乗降・認証・ギルド等」の**大区画**だけ表示。
2. **レジストリンク・ドームを選択**：環状受付、受付区画と作戦室、管理区画などの**詳細**を表示。
3. **受付などの個別区画を選択**：その区画の役割・機能・補足を詳細パネルに表示。
4. **選択解除・階層切替**：通常表示へ戻る。前の施設の詳細は残さない。
5. HTMLマップと配置エディターで同じ外形・選択条件を用い、表示差異をなくす。

### 未確定内容の扱い
- 詳細設計段階に進んでいない施設では、選択しても**「内部未設計」**と案内する。仮の受付・小部屋を公式のように描画しない。
- 細部を先に案出ししていた場合は、検討データに残せるが**確定済み外形とは区別**する。
- 地図上の色や図形は**地理的な所属・役割・通行区分**を優先して表示する。装飾目的の形を増やさない。

## 5. GitHub上でのファイル運用と承認

| ファイル | 役割 | 運用 |
| --- | --- | --- |
| `data/upper.json` / `middle.json` / `lower.json` | 現行Notionとの比較用の基準配置 | 作業中は変更しない |
| `data/upper-layout-draft.json` / `middle-layout-draft.json` / `lower-layout-draft.json` | 各階層の制作作業案 | 段階①～⑥の変更をここで行う |
| `index.html` | 設計を確認する閲覧マップ | 通常表示は大枠、選択すると細部 |
| `editor.html` | 配置調整・選択 | 表示と外形を閲覧側にそろえる |
| `docs/` | 段階ごとのルール・差分・設計メモ | 決定済み／未決定／警告を明記 |

制作の各段階は次の管理状態を用いる。
- **作業中**：GitHubで案を編集、Notionには未反映。
- **大枠確認済み**：ユーザーが外形と街区配置を確認した状態。細部は未確定。
- **接続確認済み**：道路、ゲート、避難、一般／専用移動の整合を確認した状態。
- **内部設計確認済み**：機能区画と詳細を検証した状態。
- **完成承認済み（Notion反映待ち）**：GitHub完成案のユーザー承認がある状態。
- **Notion反映済み**：承認済み差分だけを書き込んで再取得・一致確認した状態。

**承認の単位は階層または施設**とする。例えば中層ターミナルの大枠を承認しても、上層全体・中層の細部・Notion書込を承認したことにはならない。

## 6. GitHub完成後 → Notion反映フロー（必須）

1. GitHubの完成版と、変更点・未確定点・旧Notionとの差分を**Markdownで提示**する。
2. ユーザーが内容を確認し、**Notionへの反映を明確に指示したときだけ**進める。GitHubの完成・コミットだけでNotionへ自動同期しない。
3. 共通参照ルールに従い、対象Notionのページを**反映直前に再取得**する。
4. **承認済み部分だけ最小限**の範囲で編集。既存設定との食い違いは勝手に補完せず確認する。
5. 反映したNotionを再取得し、GitHub承認案との差分を確認する。
6. 必要なら比較用基準配置JSONをNotionの**更新後設定に合わせて別途同期**し、GitHubの案と正本の状態を混同しない。

### 禁止事項
- 大枠未決定なのに受付や小部屋を先に公式の位置として確定する。
- 外部未接続を内部の見た目で補う、近接だけで通行可能とする。
- 地区全体を単一の巨大建物として解釈する。
- GitHubで作業中の案をNotionに逐次上書きする。
- ユーザーの完成承認なしにNotionへ反映する。
