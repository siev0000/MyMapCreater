# AA共通マップエンジン v2｜中層再生成と実装状況

> 2026-11-08 更新。GitHub下書き専用。Notion正本・比較用確定JSONは変更しない。

## 本実装で反映したこと

- 新規 aa-map-engine.js で既存 data/*-layout-draft.json を読み取り専用で正規化する。
- 地区、施設、部屋、通路を共通の型と属性に変換。内部配置は親を基準とした相対座標へ変換し、絶対描画座標は親子の変換から計算する。
- footprint 多角形、矩形、円環、中心線の道路と実際の幅（m）を区別して保持する。
- 中層の大枠／中枠／小枠の表示階層は選択状態で切り替える。ズーム倍率だけでは階層を変えない。
- index.html、editor.html、overview.html の中層中枠・小枠の形状と親子判定を共通化。比較画面B案の地区・加工施設・道路を中層レイアウトJSONから再描画する。
- 配置エディターは初期状態で選択・閲覧専用。編集モードをONにした場合だけドラッグで編集できる。
- 配置エディターのGitHub保存先を data/<floor>-layout-draft.json に修正。
- preview/middle-regenerated.svg は現行下書き座標を元に作成した確認用画像。生成コマンド: node tools/regenerate-middle-preview.cjs
- 回帰確認: node tools/test-map-engine.cjs

### 中層の保護対象

- 4地区: core_shell_town、refine_valley、stern_core_shell_town、stern_refine_lab_district
- 地区外形の多角形、色分け、中心位置、寸法を維持。
- 加工施設4棟: standard_fuel_factory = 160×120m、plant_oil_processing = 100×80m、fiber_resin_processing = 120×100m、middle_material_processing = 140×100m。元の配置座標を維持。
- 工場や地区の未確定性を消さない。道路は近接や線の交差だけで接続確定しない。
- 三階層の既存比較用 data/upper.json、middle.json、lower.json は変更しない。

## 共通エンジンに登録する基本仕様（採用済み・段階実装）

| 項目 | 採用仕様 | 実装状況 |
|---|---|---|
| 基本オブジェクト | 地区・施設・部屋・壁・扉・経路・構造物・検問・階層接続を基本種類として固定、派生属性追加可能 | 基本の地区・施設・部屋・経路を実装 |
| 子座標 | 親基準の相対座標、絶対座標は計算 | 実装 |
| 壁 | 線で作成、厚さは壁ごとに指定 | 編集機能は未実装 |
| 通路 | 中心線＋幅、端点吸着後の確認で接続を確定 | 形状の共通モデル化済み。接続編集は未実装 |
| 扉 | スライド式を標準、開き戸は選択可能。閉状態の位置を壁の隙間に沿った点線で表示 | 未実装 |
| 認証と検問 | 🔑 鍵、💳 カード、🤖 検問は扉と別オブジェクト | 未実装 |
| 外壁 | 施設・部屋の外壁は必要な場合にだけ自動生成 | 未実装 |
| 上下階 | 接続設備を選択後「移動先を表示」 | 未実装 |
| 表示階層 | 選択で変える。ズームは文字・記号の視認性だけ変更 | 中層の大中小は実装 |
| エディター | 選択と編集を分離 | 初期状態の操作を分離 |
| テンプレート | 配置後は独立、再適用は任意 | 未実装 |
| 保存検証 | 致命的エラーのみ確定保存を禁止。警告付きの配置は保存可能。作業用下書きは常に保存可能 | JSON基礎検証のみ。全自動検証は未実装 |
| 親の削除 | 内部ごと削除／内部を上位階層へ残す／キャンセル | 未実装 |
| 自動補正 | 編集対象と内部のみ。固定柱は位置を変えず施設へ取り込み、プレビュー後に確定 | 未実装 |

## 次に実装する工程

1. **データモデル拡張**：壁・扉・検問・階層移動・各種接続の属性、ID、親子・関連関係を実装。旧JSON互換を維持。
2. **共通描画**：通常マップ・エディターの壁／扉／道路／構造物を共通の形状・当たり判定で扱う。中層固有の特殊図形処理は徐々に撤去。
3. **接続管理**：スナップと実際の通行接続を分けて管理。壁の開口部、扉の状態、立体交差、階層接続、通行対象を検証。
4. **編集操作**：頂点操作・回転・複製・親子削除・編集履歴・テンプレート。
5. **自動形状補正**：柱の取り込み、壁・通路の補正、生成予定物の差分表示、確認後の一括適用・Undo。
6. **検証と移行**：全3画面、3階層の描画・選択・スマートフォン操作、JSON往復保存、確定保存前の致命的エラーチェック。
