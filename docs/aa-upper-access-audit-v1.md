### 追加の干渉
- M門 (0,-750) から環状路近傍 (0,-600) への最短の直線は、居住・待機区の占有範囲と干渉する。道路を単純延長しない。
- E門 (-400,180) はエイドロン環状路の候補線 (-440,200) から約45mにあるが、道路中心線が施設外形に近接・重複するため、道路を確定線として扱わない。
- 再配置案 `roads[]` は多数に `draft_route_requires_review` ステータスが付いており、構造柱・隔壁の確定位置決定より先に経路と建物の交差確認が必要。
- 現行マップの構造レイヤーは干渉条件によって柱と隔壁の描画を抑制する**参考線**であり、通行可否の根拠にしない。

## 接続調整方針（現段階では道路追加・道路変更しない）
1. 既存の建築配置案は一旦固定し、M・Eの各認証門を個別の保護施設として保持する。
2. 認証門から **中央共有区** と **各研究区の環状路** まで、双方に接続する実際の通行可能ルートを設計する。
3. 関係道路と施設多角形の間に、**道路半幅＋壁・余裕幅** を確保して交差を判定。道路と別経路が交わっても無条件に相互接続としない。
4. 既存門の移動が必要な場合でも、Notion正本との違いを明示して別案に分岐させる。勝手に確定しない。
5. 道路が定まった後で、認証門の境界線・隔壁の切欠き・避難路と構造柱を確定する。

## 表示と編集の権限
- `index.html` の「構造柱・隔壁（仮）」をONにすると、上層の黄色の「!」が認証門と認証通路の位置ずれを示す。
- その警告は**つながっていないこと**を意味し、破線を実際に通行できる経路として扱わない。
