関連タスク：[06-roadmap-and-acceptance.md](specs/06-roadmap-and-acceptance.md)

## 1. 確定した方針

- **MyMapCreaterは2Dマップ制作・編集を主機能とする。** 実在地域OSM/DEM取得は制作のための補助機能。
- 現時点では3Dビューアや3Dエディターの実装を急がない。2Dの道路・区画・建物・地形・施設・内部構造の制作と保存・復元を優先する。
- 将来、**一つの共通マップデータを2Dと3Dで別々に描画**できるようにする。3Dの都合で2D編集UIを置換しない。
- 平面のX/Yだけでは復元できない高さ・階・地面との関係は、2Dの制作時から保存できるように拡張する。**不明値を0mとして確定しない。**
- 既存のScene v2、マップと施設の座標・形状・色、親子階層、住宅テンプレート46件、既に取り込んだ咲花駅データは保護する。
- 現在の2Dデータだけで屋根形状、建物内部全体、崖・洞窟、立体交差を完全復元できるとは扱わない。不足する部分は将来手入力または専用設定を追加する。

## 2. 現行データで使えるもの（2026-11-09時点）

| 対象 | 既存の表現 | 3D化に向けた不足 |
|---|---|---|
| 平面形状 | `rect`/`polygon`/`polyline`/`circle`/`ring`、世界座標X/Y | 高さ方向の意味づけ |
| 咲花駅の地形 | 500m四方、DEM由来の20×20=400標高セル、25mピッチ | セル平均値のため詳細起伏が失われている。元DEM格子・欠測・解像度の独立保持 |
| 道路・線路 | 経路頂点、表示幅（推定値あり） | 各頂点高さ、交差点の接続／上下関係、橋・トンネル |
| 建物 | 輪郭、階層・一部高さm、建物テンプレート／内部JSON | 地盤高、正確な階高、屋根形状、地面との接地 |
| 地理情報 | 中心緯度経度、世界座標への換算（咲花駅は1m=4単位） | 全マップでの高さ基準・単位統一 |
| 家具・設備 | 図形、親子関係、階など | 床からの設置高や実寸高さ |

注：咲花駅のGitHub公開版は圧縮表示用スナップショット。原本JSONの全OSMタグや座標精度を保持した完全コピーではない。原本編集が必要な場合はユーザー保存済みのJSONを使用する。3D化に際して、公開版の丸めた値を「原本の測量値」と扱わない。

## 3. 将来のデータ設計イメージ（検討中、現行形式への追加をまだ確定しない）

- **地形**：描画用の400個の矩形と、真の地形標高グリッドを分離。グリッドには原点・セルピッチ・高さの基準・標高・欠測・出典・取得日時を保持する。描画用の矩形はそこから生成してよい。
- **道路**：平面の折れ線を残し、頂点ごとの高さ、地形への追従指定、橋／トンネル／盛土／切土などを別属性で記述する。平面的に交差しても高度が違えば接続しない。
- **建物**：建物輪郭はそのまま残し、地盤高、外壁高さ、各階の床高、屋根の形式などを任意属性として追加する。未指定の屋根を実測値として生成しない。
- **施設／設備**：床の所属階と地盤・床からの相対高さを区別。
- **単位**：マップの水平座標単位と標高mの換算・基準を明示。高さの出典は **実測／推定／手動変更／未設定** を区別する。
- **互換**：新フィールドは段階的に追加。既存シーンに高さがない場合でも従来どおり2D描画可能とする。保存前にScene v2チェックと旧ファイル再読込を行う。

以下は概念例であり、**決定済みJSONスキーマではない**：

```json
{
  "terrain": {
    "origin": [0, 0],
    "cellSizeWorld": 100,
    "elevationUnit": "m",
    "heightDatum": "to-be-defined",
    "samples": [null, 25.3, 26.0],
    "source": "DEM"
  },
  "objectElevation": {
    "groundM": null,
    "heightM": null,
    "provenance": "unknown"
  }
}
```

## 4. 作業順（タスクへの対応）

1. **現行データ調査**：咲花駅の400セルと建物高さ、道路幅、既存施設の階情報を確認し、未設定や推定値を区別する。
2. **スキーマ設計**：地形標高の独立管理と高さ情報の任意属性を定義。既存Scene v2との互換・移行手順を確認。
3. **2D制作機能の仕上げ**：道路の交差・接続、地形のブラシ・斜面表示、輪郭を利用した建物配置、Undo/Redo、保存・復元を実装・検証。
4. **高さ情報の入力**：道路・建物・設備に必要な高さ・地形追従を2D画面から入力できるようにする。
5. **将来（別フェーズ）**：共通データから3D地形メッシュを生成する試作プレビューを追加。2D表示・JSONを変えず切り替えられるか検証。
6. **将来（その後）**：道路・建物の3D表示、橋／トンネル、必要な当たり判定・立体設備を段階導入。

## 5. 現時点の実装・未実装

**実装済み（一部要テスト）**：2D Scene v2編集、OSM/DEM取込、咲花駅標高セル、標高セル範囲の一括編集、道路端点の簡易接続、選択輪郭位置を基準とした建物テンプレート配置。

**未実装**：独立した標高グリッド正本、滑らかな斜面編集、立体交差の道路接続、建物・道路の地面追従、汎用高さスキーマ、3Dプレビュー・3Dエディター。

**未確認**：主要ブラウザー／スマートフォン実機での操作、3D描画性能、標高精度・欠測処理の妥当性。テストが通っても実画面確認済みとはみなさない。

## 6. 変更禁止・引き継ぎ時の注意

- 3D化のために既存の2Dマップを破棄・自動変形・勝手に配置補正しない。
- 咲花駅の保存済みデータを表示用圧縮版だけで上書き・消去しない。
- 3D仕様の検討を理由に現在の2D制作を止めない。
- タスクとメモの更新は**設計記録の更新**であって、3D機能が実装・動作確認されたことを意味しない。
